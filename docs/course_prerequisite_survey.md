# 选课前置问卷

在 `config.json` 的 `course` 中添加如下配置（修改后重启应用进程）：

```json
"prerequisite_survey": {
    "enabled": true,
    "rules": [
        {"pattern": "^S2026", "survey": "2026级选课前置问卷"},
        {"pattern": "^S2025", "survey": "2025级选课前置问卷"}
    ],
    "fallback": "选课前置问卷"
}
```

- 配置缺失或 `enabled: false` 时关闭，保留原选课行为。
- 按数组顺序对当前 `User.username` 使用 Python `re.search`，区分大小写，首个匹配生效。需要全串匹配时使用 `^...$`。JSON 中的反斜杠需要转义，例如 `"^S\\d+$"`。
- 无匹配规则时使用必填的 `fallback`。名称与问卷 `Survey.title` 精确匹配；管理员应确保所选名称唯一。
- 在问卷管理中先创建对应问卷、题目和选项，再发布并设置填写时间。模板中的名称是示例，不会自动创建问卷。
- 开启后，仅具有选课页面访问权限的学生（`NaturalPerson.identity == STUDENT`）必须提交对应问卷；教师不需要填写，仍受原有页面权限和选课操作限制。学生身份以个人档案为准，不单独根据 `User.utype` 判断。草稿、其他账号的答卷、其他问卷的答卷均不算完成。
- `/selectCourse/` 和 `/yppf/selectCourse/` 同时保护 GET 与选退课 POST。未完成者在该入口填写问卷，提交成功后重定向回原入口。普通浏览器与 WebView 使用同一个表单，提交需携带 CSRF token。
- 填写流程独立于宿舍分配页面，支持文本、单选、多选和按编号输入的排序题。已有草稿会回填，提交时调用通用问卷提交操作，校验所有必填题、选项和开放时间后才转为 `SUBMITTED`。
- 正则/配置错误、所选问卷缺失或重名会阻止访问并提示联系管理员。未提交用户遇到未发布或不在填写时间内的问卷也会被阻止；已经提交者不受问卷随后结束的影响。
- 如需每学期重新填写，请使用新的唯一问卷名称并更新配置。此功能无需数据库迁移，也不会改写已有 `config.json`。

## 创建 2026 秋在校生追踪问卷

管理命令 `create_student_tracking_questionnaire_2026` 从本地 JSON 数据创建两份问卷，
标题与配置模板一致：

- `2026 秋元培在校生追踪问卷（新生版）`：第 1–11 题。
- `2026 秋元培在校生追踪问卷`：第 1–21 题。

题目数据保存在 `raw_data/student_tracking_survey_2026.json`，不纳入版本控制，运行前需自行提供。
运行命令无需 Word 文件或
Word 解析依赖。题目及选项保留原顺序，包含第 7 题的注意力检查提示、第 11 和 16 题的反向
选项顺序。全部题目设为必填；第 21 题为多选，最少和最多均为 6 项。

导入前会校验 JSON 恰好包含 21 题，题号必须按整数 1–21 连续排列且不重复，
第 1–20 题必须为 `SINGLE`，第 21 题必须为 `MULTIPLE`。校验失败时不会创建任何问卷。

通过以下命令创建（将 `admin` 替换成已有创建人账号，起止时间替换成实际开放时间）：

```bash
docker compose -f .devcontainer/docker-compose.yml exec -T yppf \
    python manage.py create_student_tracking_questionnaire_2026 \
    --creator admin --start "2026-09-08 08:00:00" --end "2026-09-30 23:59:59"
```

默认创建草稿；确认内容和时间后可在后台发布，或首次执行时加 `--publish` 直接创建发布中的
问卷。时间为部署环境的本地时间，不带时区。此命令不修改本地配置，也不会自动开启前置问卷。

重复执行只创建缺失的版本，保留已有问卷、题目、答卷、状态和时间；`--publish` 不会发布已存在
的草稿。已有重名问卷时整次操作回滚并报错。命令使用 MySQL 命名锁避免多个该命令同时创建
重名问卷；执行期间不要在后台手动创建同名问卷。两版创建处于同一事务，失败不会留下半份问卷。
